## Design and ownership boundary

The canonical DeckSpec v1 remains tool-neutral and unchanged. Adapter-specific asset and diagram metadata stays under `extensions.presentation_marp`; source and data references remain owned by the canonical deck. Charts are derived only from finite numeric `data_refs`; factual charts are never generated by an image model. Architecture diagrams use a bounded declarative node/edge model and produce deterministic passive SVG. The editable diagram source is retained as a separate JSON artifact with a content hash. Tables render directly from the referenced data; values are not retyped in exhibit markup.

Every staged asset must identify its local path, asset ID, source ID, license/rights, as-of value, alternative text, owner and confidentiality classification. Paths remain relative and confined to the input root. Remote URLs, symlinks, active SVG and unlicensed/missing metadata are blocked. An explicitly declared local raster fallback may be used only for a supported mode limitation; it cannot hide invalid/unsafe SVG or silently change output mode. If neither the declared source nor fallback is usable, return a bounded blocked result.

CI uses synthetic fixtures only. The existing renderer is network-isolated; no actual external provider is called. A synthetic confidential-classification sentinel may test metadata handling, but it contains no private or customer information. Cloud Next runtime and deployment are reviewed N/A because this increment changes only the unregistered isolated adapter and does not change a packaged skill/runtime contract. This does not satisfy parent #283.
