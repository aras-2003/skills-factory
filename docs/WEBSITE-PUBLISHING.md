# Public catalog updates

GitHub Pages serves `main:/docs`. A passing PR merged into main triggers the existing Pages publication. This site is a source catalog; it is separate from the private Cloud Next MCP deployment.

- `scripts/catalog/generate_catalog.py` regenerates `CATALOG.md` and `docs/catalog.json`, including every source skill and workflow. The preserved catalog source revision describes that source snapshot; refresh it deliberately when publishing a newly verified source snapshot.
- `docs/processes.json` contains curated reading paths. Cover new domains with their actual source skills, stage gates and source links; keep draft maturity visible. `docs/index.html` supplies Polish domain labels and renders the full workflow list directly from generated catalog data, so source workflow discovery does not depend on curated path coverage.
- `docs/lab-release.json` is the manifest of the last verified immutable Lab build. Copy it from the matching validated artifact, not from an older tracked plugin snapshot. CI packaging uploads its new receipt as an artifact without updating this branch. The current public receipt records Lab 0.35.0 built from `e1c4b8462c519f1fa25a9af5980b6786ed590029` and included in main merge `9a7f4132baeaf226944747876f47e1bfb283d4d7` (PR #315).
- `docs/cloud-release.json` is a dated, public-safe snapshot of the last verified private MCP deployment. Refresh it only after native deployment success and live identity/catalog checks. Record the Site version/SHA separately from embedded Lab and draft source provenance. Exclude tokens, user identities, private inputs and access policies. The verified Site v23 exposes all 83 Lab components: 64 source skills and 19 workflows, with no separate draft extension. `draft_extension: null` is valid; the public page supports both full-Lab and historical extended catalogs.

Do not infer model quality or native authoring/export success from loader checks. The public receipt must preserve NOT_RUN for those campaigns until real evidence exists.

Hero counters derive from the complete observed MCP `catalog_entries` array, never manually maintained summary numbers or the source skill count. Refresh it using authenticated `runtime_info` and `list_skills` outputs from the same live Site revision, then run `scripts/catalog/sync_cloud_catalog.py --runtime <runtime-output.json> --catalog <catalog-output.json>`. The sync rejects unverified identity, mismatched Site/embedded revisions, duplicate names, catalog digest mismatches and runtime names absent from source. Semantic domains come from source taxonomy because the flattened Lab package directory is not a domain. Store only the public-safe resulting metadata in `docs/cloud-release.json`. Raw temporary tool outputs are not committed. The public site displays the observation date; it cannot read the owner-private MCP directly without authentication and must not imply a live anonymous connection. Every source workflow is included in the v23 MCP catalog.

Before merging, run the site catalog contract tests, regenerate the catalog and check the diff. Inspect desktop and mobile behavior in the app browser, including domain names, new reading paths, workflow search, source links and modal details. After merging, verify the Pages build and the actual published page. This update does not change Pages hosting, access rules or private MCP publication.
