# Executive Role Evaluator — Behavioral Evaluation

Date: 2026-09-30  
Candidate: `executive-role-evaluator` v0.1.0  
Mode: model-assisted dry run against committed eval cases  
Disposition: **PASS WITH FOLLOW-UP**

## Scope

This evaluation checks observable behavior against the committed routing and behavioral cases.

It does **not** yet prove native ChatGPT plugin routing. Native routing is the release follow-up after production packaging.

## Case matrix

| Case | Result | Key observations |
|---|---|---|
| inflated-cto-title | PASS | Title was not treated as proof of authority; no-team/vendor-heavy setup was treated as a mandate risk; decision stayed investigative while authority remained unknown. |
| deputy-cio-major-enterprise | PASS | Recognized bridge-to-CIO value and scale without requiring full CIO scope; separated exposure, mandate and operating ownership. |
| high-paying-narrow-role | PASS | Compensation was separated from career value; narrow platform scope and reporting distance were treated as trajectory risks. |
| lower-title-larger-mandate | PASS | Lower title did not suppress assessment of CEO reporting line, 150-person organization, budget ownership and executive committee exposure. |
| transformation-without-authority | PASS | Detected accountability/authority mismatch and elevated governance, budget and escalation rights as critical unknowns. |
| incomplete-recruiter-message | PASS | Refused false precision; kept role fields unknown, confidence low, and generated only high-impact discovery questions. |
| company-research-only negative | PASS | Should route away from the evaluator to company-context research. |
| CV-tailoring-only negative | PASS | Should route away from the evaluator to CV tailoring. |

## Behavioral findings

### Strengths
- Strong separation of role quality, candidate fit and career value.
- Correct treatment of mandate/authority as a structural gate.
- Good incomplete-information behavior.
- Avoids title and compensation bias.
- Output contract is decision-oriented rather than descriptive.
- Candidate-specific context is externalized instead of embedded in the reusable skill.

### Residual risks
1. **Native routing not yet verified** — the two negative cases are validated at contract level, but must be tested after plugin installation.
2. **Potential output verbosity** — the full output template can be too long for simple recruiter-message cases. Runtime should compress sections when evidence is sparse while preserving mandatory decision fields.
3. **Score precision** — numeric scores are useful for consistency but should be omitted when evidence is too weak. The current contract already permits `insufficient evidence`.
