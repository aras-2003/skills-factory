# Skills Factory agent instructions

For Skills Factory Cloud Next or Site changes/publication, read `docs/SITES-PUBLISHING.md` from this repository's current main and the installed Sites hosting skill. The canonical MCP adapter is `adapters/skills-factory-cloud-next/`; the Site application is `sites/skills-factory-site/`. The provider-managed Site repository is a deployment mirror only; never author changes there without first applying them here.

A user publication request authorizes ordinary in-scope work. Network/terminal approval and credential-delivery approval are separately enforced. Hidden stdin prevents display but does not authorize transfer. DNS failure is not an approval rejection; use the runbook's reviewed execution path. If credential delivery is explicitly rejected, stop that path, preserve edits and report the actual reason. Do not reroute a rejected transfer or assume a model/chat switch supplies permission. Do not invent a user approval button.

GitHub main and the provider-managed Sites deployment mirror are separate. GitHub main updates do not publish the Site automatically. Generate the Cloud Next adapter bundle, Site catalog and canonical source attestation from the same Skills Factory commit, then synchronize the Site workspace with `sites/skills-factory-site/scripts/sync-site-source.mjs` inside the official Sites workflow. Use native deployment tools; Git inside that workflow is expected. Preserve source history, Site/plugin identity and audience. Confirm the actual deployed version and mirror SHA separately from the canonical Skills Factory SHA and embedded Lab provenance. For Chat tests, explicitly select Cloud Next and verify actual tool invocation.
